# Couple Home：Railway 部署包

此包复用已验证的独立 Node.js 版。数据和照片放在 Railway 持久卷，更新镜像不会覆盖它们。
运行进程会在准备卷目录后降为 UID/GID 1000。不依赖 ChatGPT 登录、D1、R2 或 AI 服务。

## 构建与上传

云环境中的 CLI 安装、代理下载、授权和上传注意事项见 [CLI.md](CLI.md)。

在源码根目录执行：

```sh
pnpm run build:node
node deploy/railway/pack.mjs
```

最后一行输出新建的部署目录。只从该目录上传，不能上传整个工作区。
部署包只包含程序、迁移、静态资源、许可证和部署说明；不含账号、数据库、照片或密钥。

Railway 新服务使用部署目录的 Dockerfile 构建。不要选择仓库默认的 Workers 启动命令。
Railway 已宣布淘汰旧 railway.toml/railway.json 配置，新服务设置应使用当前控制台、CLI/API 或 Infrastructure as Code。

## 必需服务设置

- 一个服务、一个实例，添加持久卷并挂载到 `/persist`。不要添加第二个免费服务或付费数据库。
- 创建 Railway 提供的公网 HTTPS 域名。
- `APP_ORIGIN` 设置为该完整 HTTPS 来源，不带路径或末尾斜线；也可使用注入的 `RAILWAY_PUBLIC_DOMAIN` 自动推导。
- 保留平台注入的 `PORT`，监听 `0.0.0.0`。健康检查路径 `/healthz`，超时 120 秒。
- 数据目录为 `/persist/data`，本地快照目录为 `/persist/backups`；可由 `DATA_DIR` 和 `BACKUP_DIR` 覆盖，但必须仍在卷内。
- Railway 环境缺少卷时程序拒绝启动，避免误把真实数据写入临时磁盘。
- 私人照片仍经会话验证的 API 读取，不开放对象目录；剩余空间不足时停止照片上传，为数据库保留空间。
- 原应用只信任同机反向代理，所以这里不信任外部转发 IP 头；登录限流可能按 Railway 代理地址合并计算。

## 首次使用

部署后先用隔离的测试数据验收。公网首次设置需要私有初始化码，它保存在卷的 `data/.setup-code` 中，
可由账号持有者通过 Railway 的私有文件管理或终端查看。不要公开初始化码、不要贴到聊天或提交 Git。
随后在网页设置两个不同的成员密码，第一位成员拥有管理权限。初始化后不能再次覆盖小屋。

## 免费范围与费用

当前官方文档列出 Free 每月 1 美元使用额度及 0.5GB 持久卷。首次注册的 5 美元试用额度不能视为长期免费保障。
保持 Free，不绑定或升级付费套餐，不自动增加存储。核实账号实际权益、额度耗尽和数据保留政策。
初期仅用测试账号和少量照片，观察用量后才决定是否存放真实回忆。
服务空闲休眠可降低用量，但有冷启动；健康检查只在部署时执行，不是持续监控。
任何平台的免费政策都可能变化，不能承诺永久零费用或永久保留数据。

## 备份与更新

网页管理员可以下载包含记录和照片的完整备份。先做备份再更新，确认两位成员、记录和照片在重新部署后仍存在。
服务器快照命令（在容器内、以 UID 1000 执行）：

```sh
DATA_DIR=/persist/data BACKUP_DIR=/persist/backups node /app/app/backup.mjs
```

快照包含密码哈希、会话和未到期信件，必须私下保存。0.5GB 卷不能无限累积快照。
至少另存一份到你控制的其他设备或私人存储，实际做一次隔离恢复验证。
本包没有配置自动站外备份；同一持久卷上的备份不能抵御卷丢失。

## 上线验收

1. HTTPS 首页、静态资源、数据库健康检查正常。
2. 两位成员分别登录，时间线新增和双方同步正常。
3. 照片上传、私有下载正常；退出后记录、照片和备份不可读取。
4. 普通成员不能操作管理员密码或完整备份；伪造身份头不能访问私人数据。
5. 重启并重新部署后，账号、记录、照片保持；再次初始化被拒绝。
6. 完整备份可在隔离小屋恢复；验证照片字节与记录一致。
7. 确认月度用量和剩余容量，再投入真实数据。
